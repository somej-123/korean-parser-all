# 실제 문서 구조 정확도

합성 정답 세트(`benchmarks/eval`)는 우리가 만든 문서라 실제 문서의 표·제목을 얼마나 맞히는지 알 수 없다. 그래서 실제 공공
문서 6개에 사람이 직접 정답(제목 목록, 표 구조)을 달아 잰다 (2026-10-18).

```bash
python benchmarks/real_truth/score_real.py --truth samples_rfp/real_truth --out benchmarks/real_truth/report.md
```

정답 파일은 원본의 글을 담으므로 저장소에 넣지 않는다 (`samples_rfp/real_truth/*.truth.json`, 저장소 밖). 이 폴더에는
도구와 숫자 보고서(`report.md`)만 둔다. 다른 파서의 결과는 `benchmarks/compare`가 모아 둔 것을 쓴다.

HWP는 우리 파서와 상관없이 표 구조를 읽을 도구가 없어(한글 자동 조작의 파일 열기는 보안 승인이 필요하다) 넣지 못했다.

## 정답 만든 방법

- **표 (HWPX·DOCX)**: 파일의 표 정의를 우리 파서를 쓰지 않는 작은 스크립트로 읽었다 (`draft_from_xml.py`: HWPX
  `cellAddr`·`cellSpan`, DOCX `gridSpan`·`vMerge`). 2행·2열 이상인 표만 넣고 한 줄짜리 제목 상자는 뺀다. 표 안의 표가 있는
  문서는 쓰지 않았다 (지금 표 지표가 표 안의 표를 다루지 못한다).
- **표 (PDF)**: 쪽 그림을 보고 머리행·병합 칸을 직접 적었다. 데이터 칸은 그림에서 잰 열 경계와 쪽 그림에서 찾은 가로줄로
  나누고, 그 안의 글자 층 글자를 넣었다. 쪽을 넘어 나뉜 행(94번)은 한 행으로 합쳤다. 몇 행은 그림과 맞대어 확인했다.
  쪽을 넘어 이어지는 표는 보는 방법에 따라 정답이 달라서 둘 다 잰다: 하나의 표(moj), 쪽마다 머리행이 되풀이되는 표
  12개(moj_pages).
- **제목**: 사람이 원본 모양을 보고 정했다. 문서 제목, 장·절 제목(번호와 짧은 제목만 있는 줄, 제목 스타일), 부록의
  번호 제목을 넣는다. 번호 뒤에 바로 문장이 오는 줄, 개조식 항목(□ ○ ㅇ -), 자리표시('…'), 표 안의 글은 넣지 않는다.
  DOCX는 LibreOffice로 PDF를 만들어 모양을 봤고, HWPX는 파일 안의 한글 미리보기 글로 순서와 번호를 확인했다.
- 손으로 옮긴 글은 원본 글자 층·XML과 맞대어 확인했다 (법무부 머리행의 '밀집지역 외국인'을 처음에 잘못 읽어 고쳤다).

지표는 정답 세트와 같다 (`benchmarks/eval/metrics.py`): 제목 재현율·정밀도·단계 일치(정답 제목 목록이 그 문서의 제목
전부라고 본다), 표 TEDS(정답 표마다 가장 비슷한 예측 표, 칸 글의 빈칸은 빼고 비교).

## 결과 (`report.md`)

처음 잰 결과(v1.0.0)에서 드러난 문제를 두 번에 걸쳐 고치고 다시 쟀다. 정답은 고치기 전에 두 번 바로잡았다:
가스공사에서 규칙에 맞는 용어 제목 3개(3.1·3.3·3.4)를 빠뜨린 것(42 → 45개), 자동 번호가 붙은 DOCX 제목을 화면에 보이는
글과 달리 번호 없이 적은 것('개요' → '1. 개요'). 다른 파서도 같은 정답으로 다시 쟀다.

| 파서 | 제목 재현율 | 제목 정밀도 | 표 TEDS | 잰 문서 |
|---|---:|---:|---:|---|
| korean-parser v1.2.0 (추정 제목 포함) | **0.963** | **0.893** | **0.988** | 6 |
| korean-parser v1.0.0 (추정 제목 포함) | 0.513 | 0.688 | 0.827 | 6 |
| Docling | 0.607 | 0.495 | 0.939 | 3 (PDF·DOCX만, 법무부 PDF는 시간이 오래 걸려 빠짐) |
| kordoc | 0.344 | 0.500 | 0.721 | 6 |
| MarkItDown | 0.183 | 0.375 | 0.375 | 4 |

(v1.0.0 행은 정답을 바로잡기 전 값이다. 나머지는 바로잡은 정답으로 잰 값이다.)

고친 것:
- **쪽을 넘는 PDF 표** (v1.1.0): 두 쪽씩만 잇던 것을 끝까지 잇고, 두 줄 머리 행 되풀이도 뺀다. 법무부 12쪽 표
  '하나의 표' 정답으로 TEDS 0.172 → 0.977. 쪽이 바뀌는 곳에서 나뉜 행 4개는 아직 따로 남는다 (세로 병합 칸과 구별이
  어렵다). '쪽마다 표' 정답으로 보면 0.008이다 (쪽마다 따로 내는 PyMuPDF4LLM·opendataloader-pdf는 0.93).
- **번호 소제목** (v1.1.0): 점이 여러 개인 절 번호, 표 바로 위 번호 줄, 차례로 이어지는 한컴 기호 번호(❶ ❷)를 추정
  제목으로 본다. 가스공사 0.133 → 0.978, 동래구·보도자료 0 → 1.000.
- **추정 제목 단계** (v1.2.0): 절 번호는 점 개수로 단계를 정하고(6.6.1이 6.7보다 위 단계가 되던 것), 자동 번호도 보이는
  번호 모양으로 종류를 정한다(자동 '1.'과 직접 친 '2.'가 다른 단계가 되던 것). 단계 일치 가스공사 0.726 → 1.000,
  동래구 0.333 → 1.000. 절 번호 줄은 영문 제목 때문에 60자까지 본다.
- **PDF의 제목 아닌 큰 글씨 줄** (v1.2.0): 날짜뿐인 줄, '- 다 음 -', 문장으로 끝나는 줄은 문단으로 되돌린다. 한남대
  공고서 정밀도 0.625 → 0.714. 괄호로 감싼 줄('<자료 검색>')과 끝의 서명 줄은 그대로다: 실제 PDF 전체에서 괄호로 감싼
  제목 266개는 대부분 표·그림 제목이라 한 문서의 판단으로 뺄 수 없다.
- **표 구조 자체는 정확하다**: HWPX·DOCX 표 TEDS 0.964~1.000.

남은 것: 번호도 스타일도 없이 큰 글씨로만 쓴 DOCX 제목('개정 이력'), PDF 서명 줄, 쪽 사이에서 나뉜 표 행.

한계: 문서 6개, 제목은 사람의 판단이다. 이번 고침은 이 정답을 보고 한 것이라 같은 문서로 잰 숫자는 좋게 나올 수밖에
없다. 처음 보는 문서로 다시 재야 일반적인지 알 수 있다.
