# 이 프로젝트의 범위

korean-parser-all은 **문서 파서(엔진)**다. 원문에 있는 것을 빠짐없이 읽고, 원문에 없는 것은 넣지 않고,
모든 결과가 원문의 어디에서 왔는지 되짚을 수 있게 하는 데까지가 역할이다.
분류, 임베딩, 검색, 정보 추출처럼 내용을 해석하거나 쓰는 곳마다 답이 달라지는 일은 **후속 프로젝트**가 맡는다.

## 나누는 기준

| 질문 | 예 | 맡는 곳 |
|---|---|---|
| 원문을 보면 정답이 하나로 정해지는가? | 병합 칸 수, 글자 굵기, 읽기 순서, 쪽·좌표 | 이 프로젝트 |
| 쓰는 곳에 따라 답이 달라지는가? | 조각 크기, 임베딩 모델, 검색 방식 | 후속 프로젝트 (이 프로젝트는 설정값으로만 받는다) |
| 내용의 의미를 해석해야 하는가? | 사업금액, 문서 종류 분류, 요약, 위험 조항 | 후속 프로젝트 |

## 이 프로젝트가 하는 일

| 영역 | 내용 | 위치 |
|---|---|---|
| 읽기 | 형식 판별, DOCX·HWPX·HWP·PDF·PPTX·XLSX 파싱, 손상·암호화 파일 안내 | `parsers/` |
| 구조 복원 | 텍스트, 제목 계층, 번호·개조식, 표(병합·서식), 도식·차트, 이미지, 각주, 머리말, 읽기 순서 | `parsers/`, `outline.py` |
| 원문 복원 | 원문이 손상된 경우만 되살림: 문자 정규화, PDF·OCR 띄어쓰기, 스캔 PDF의 OCR | `normalize.py`, `spacing.py` |
| 출처 | 모든 블록의 id, 파서, 쪽, 좌표, 신뢰도. 읽지 못한 부분은 `warnings`로 알림 | `ir.Provenance` |
| 보여 주기 | 같은 문서 모델을 HTML(원본 모양) · LLM 텍스트 · JSON으로 | `render/` |
| 보조 도구 | 문서 구조를 쓰기 편하게 넘겨 주는 선택 기능. 의미 판단 없음 | `chunk.py` (구조 기반 조각) |
| 품질 확인 | 시각 비교, 코퍼스 일괄 실행, (예정) 정답 세트와 평가 지표 | `benchmarks/` |

### 원문에 없는 것을 넣지 않는다

- 띄어쓰기 교정은 원문 텍스트를 믿을 수 없는 PDF·OCR에서만 켠다. DOCX·HWPX는 원문 그대로 둔다.
- 그림 설명을 AI로 만드는 기능은 넣지 않는다. 그림 안의 글자는 원문(PDF 텍스트 레이어, OCR)에서 읽은 것만 `inner_text`로 둔다.
- 한글이 자동으로 넣는 개체 설명처럼 원문에 있지만 의미 없는 값은 정리하되, 새 내용을 만들지는 않는다.
- 원문에 없는 해석이 쓸모 있을 때는 원본 구조를 바꾸지 않고 '추정'으로 표시해 따로 붙인다. 예: 굵고 큰 번호 문단으로 쓴
  제목은 `Heading`으로 바꾸지 않고 `Paragraph.heading_guess`(추정 단계, 판단 근거)만 붙인다 (`heading_guess.py`, v0.9).
  쓰는 쪽이 쓸지 말지 고른다.

### 청크 도구가 여기 있는 이유

`chunk()`는 문서 구조(제목 경로, 표 경계, 블록 id·쪽·좌표)만 쓰고 내용을 해석하지 않는다. 조각 크기와 토큰 세는 방법은
호출하는 쪽이 정한다. 구조를 가장 잘 아는 곳이 파서이므로 여기에 두지만, 쓰지 않아도 되는 선택 기능이다.

## 쓰는 쪽과의 약속

| 약속 | 내용 | 확인 |
|---|---|---|
| 형식 버전 | `Document.schema_version` (`ir.IR_VERSION`, 현재 1.4). 필드 추가는 두 번째 자리, 이름·의미 변경은 첫 자리를 올린다 | `tests/test_contract.py` |
| 결정성 | 같은 파일을 넣으면 블록 id·좌표까지 같은 결과 | `tests/test_contract.py`, `tests/test_pdf.py` |
| JSON 왕복 | `Document.model_validate_json(doc.model_dump_json()) == doc` | `tests/test_contract.py` |
| 블록 id | 문서 안에서 유일. HTML `data-kp-id`, LLM 텍스트 `<!-- b12 -->`, 조각의 `block_ids`가 같은 값 | `tests/test_contract.py` |
| 실패를 숨기지 않음 | 못 읽은 개체(OLE, 신형 차트, PNG로 바꾸지 못한 EMF 등)는 `warnings`에 남긴다 | `benchmarks/corpus/` |

## 함께 넘기는 메타데이터

| 단위 | 항목 |
|---|---|
| 문서 (`Document.meta`) | 제목, 작성자, 작성일, 수정일, 언어 (파일에 적힌 값 그대로), 원본 파일 이름·형식 |
| | `source_sha256`, `source_size_bytes`: 원본 파일 식별. 같은 문서가 다시 들어왔는지, 바뀌었는지 판별 |
| | `parser_version`: 결과를 만든 파서 버전. 파서가 바뀐 뒤 재처리할 문서를 고를 때 |
| | `page_count`, `page_count_source`: 쪽 수와 그 출처. `layout`(PDF, 정확) / `document_property`(DOCX가 저장 때 적어 둔 값, 실제와 다를 수 있음) / 없음(HWPX는 파일에 쪽 수가 없어 추정하지 않음) |
| 문서 | `schema_version`, `warnings`, 용지 크기·여백 |
| 블록 | `id`, `prov`(파서, 쪽, 좌표, 신뢰도), 종류, 제목 단계, 번호·개조식 계층, 서식 |
| 조각 | 제목 경로, 블록 id, 쪽, 종류, 토큰 수, 블록별 쪽·좌표, 문서 메타데이터 전체(`doc_` 접두어) |

파싱한 시각은 넣지 않는다. 넣으면 같은 파일이 같은 결과를 내지 않게 되므로, 저장하는 쪽(후속 프로젝트)이 붙인다.

## 후속 프로젝트로 넘기는 일

이 프로젝트의 결과물을 입력으로 받는다.

| 넘기는 결과물 | 형식 |
|---|---|
| 문서 모델 | `문서.json` (`Document`, `schema_version` 포함) |
| 검색용 조각 | `문서.chunks.jsonl` (글, 제목 경로, 블록 id, 쪽, 좌표, 문서 메타데이터) |
| LLM 입력 텍스트 | `문서.llm.md` |
| 화면 | `문서.html` (블록마다 `data-kp-id`. 검색 결과 강조에 쓴다) |

후속 프로젝트에서 다룰 일:

- 문서·조각 분류 (제안요청서, 과업지시서, 공고문 / 평가 기준, 자격 요건 …)
- 임베딩, 벡터 DB 저장, 검색, 재순위
- 정보 추출 (사업명, 사업금액, 기간, 평가 배점, 제출 서류 …)
- 요약, 질의응답, 문서 간 비교
- AI로 만드는 그림 설명 (넣는다면 생성된 내용임을 표시)
- 서버·API, 권한, 저장, 화면

## 이 프로젝트에 남은 일

| 단계 | 내용 |
|---|---|
| 4 | 정답 세트와 요소별 평가 지표 (글자 정확도 CER, 표 구조 TEDS, 읽기 순서) |
| 5 | (완료) HWP 5.0 v0.8, PPTX·XLSX v0.11. 남은 것: 슬라이드 원래 배치 화면, XLSX 차트 |
| 수시 | 실제 문서에서 찾은 파싱 오류 수정 (예: PDF 제목의 띄어쓰기, 다단·바탕쪽) |
