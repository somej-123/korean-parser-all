# 한국어 후처리 효과 평가

같은 내용의 DOCX(정답)와 PDF(평가 대상)를 Docling으로 변환하고,
PDF 결과의 띄어쓰기가 `korean_parser` 후처리 전후로 정답에 얼마나 가까운지 측정합니다.

```bash
pip install -e "../..[docling]"
D=../docling-cpu/samples
python evaluate.py --reference $D/사업계획서.docx --target $D/사업계획서.pdf --target $D/사업계획서_스캔.pdf
```

텍스트 레이어가 없는 PDF는 자동으로 OCR(RapidOCR 한국어)로 처리합니다.

## 지표

- **띄어쓰기 F1**: 공백을 뺀 글자열을 정답과 정렬한 뒤, 각 글자 앞에 공백이 있어야 하는지를 비교합니다. OCR 오인식처럼 글자 자체가 다른 부분은 제외합니다.
- **어절 일치율**: 정답 어절 중 결과에 그대로 나타난 비율입니다. 띄어쓰기뿐 아니라 글자 오류, 읽기 순서 오류의 영향도 받습니다.

## 결과 (`samples/` 기준)

| 문서 | 경로 | 띄어쓰기 F1 (전 → 후) | 정밀도 (전 → 후) | 재현율 (전 → 후) | 어절 일치율 (전 → 후) |
|---|---|---|---|---|---|
| 사업계획서.pdf | 텍스트 | 0.459 → **0.991** | 0.848 → 0.983 | 0.315 → 1.000 | 11.4% → **98.2%** |
| 사업계획서_스캔.pdf | OCR | 0.866 → **0.967** | 0.986 → 0.989 | 0.772 → 0.947 | 41.1% → **57.5%** |

- 디지털 PDF는 띄어쓰기가 대량으로 사라진 상태였고(긴 어절 비율 46.5%), 문서 단위로 이를 감지해 재띄어쓰기를 적용했습니다.
- 스캔 PDF는 문장부호 뒤 공백 누락("이며,각")이 주된 오류였습니다. 어절 일치율이 57.5%에 머무는 이유는 띄어쓰기가 아니라 OCR 글자 오인식("인건비" → "IARI0")과 읽기 순서 오류이며, 이는 OCR 단계에서 개선해야 합니다.
- 샘플 문서 1종 기준이므로, 실제 문서로 정답 세트를 만들어 확인해야 합니다.
